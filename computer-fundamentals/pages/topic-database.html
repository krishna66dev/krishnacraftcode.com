Topic Explanation
Read in your preferred language

A Database is an organized collection of structured data stored and accessed electronically. A DBMS (Database Management System) is software that manages databases — allowing users to create, read, update, and delete data (CRUD operations).

The most common type is a Relational Database, where data is stored in tables (rows and columns), and tables are linked using keys. The language used to interact with relational databases is SQL (Structured Query Language).

Popular RDBMS (Relational DBMS): MySQL, PostgreSQL, Oracle, Microsoft SQL Server, SQLite. Popular NoSQL databases (for unstructured/big data): MongoDB, Cassandra, Redis, Firebase.

सबसे सामान्य प्रकार रिलेशनल डेटाबेस है, जहाँ डेटा तालिकाओं (पंक्तियों और स्तंभों) में संग्रहीत होता है। डेटाबेस के साथ इंटरैक्ट करने के लिए उपयोग की जाने वाली भाषा SQL (स्ट्रक्चर्ड क्वेरी लैंग्वेज) है।

लोकप्रिय RDBMS: MySQL, PostgreSQL, Oracle, MS SQL Server। NoSQL: MongoDB, Cassandra, Redis, Firebase।

The building blocks of relational databases

Primary Key (PK)
Uniquely identifies each row in a table. Cannot be NULL or duplicate. Example: StudentID (101, 102, 103 — each unique).
Foreign Key (FK)
A field in one table that refers to the Primary Key of another table. Links tables together. Example: CourseID links Student table to Course table.
Candidate Key
Any column (or set of columns) that CAN serve as the Primary Key — i.e., all values are unique and non-null. Example: StudentID, Email are both candidate keys.
Composite Key
A Primary Key made of two or more columns together. Example: (StudentID + ExamDate) together uniquely identify an exam result record.

Normalization (1NF → 2NF → 3NF)
Organizing tables to reduce redundancy and improve integrity

Normalization is the process of organizing a database to reduce data redundancy (repeated data) and improve data integrity. It involves dividing large tables into smaller, related ones.

1NF — First Normal Form
Rule: Each column must contain atomic (indivisible) values — no repeating groups or arrays. Each row must be unique. Example: Phone numbers should be in a separate row per number, not comma-separated in one cell.
2NF — Second Normal Form
Rule: Must be in 1NF + no partial dependency — every non-key attribute must depend on the ENTIRE primary key (not just part of it). Applies to tables with composite keys.
3NF — Third Normal Form
Rule: Must be in 2NF + no transitive dependency — non-key attributes must depend ONLY on the primary key, not on other non-key attributes. Example: If StudentID → DeptID → DeptName, then DeptName should be in a separate Department table.
BCNF — Boyce-Codd Normal Form
Stricter version of 3NF. Every determinant must be a candidate key. Used when 3NF is still insufficient to remove anomalies.

Real-Life Examples
🏦
Bank System = RDBMS (MySQL/Oracle)

Your bank account data — Account table, Transaction table, Customer table — all linked by Primary/Foreign keys. Strict ACID compliance ensures ₹ is never lost. SQL queries generate your bank statement.

📱
Instagram = NoSQL (Cassandra + Redis)

Instagram stores billions of photos and social connections. Uses Cassandra (NoSQL) for massive scale and Redis (in-memory key-value) for lightning-fast feed caching. Flexible schema handles varied post types (photo, video, reel, story).

🏫
College Exam System

Student table (StudentID PK, Name, Branch), Course table (CourseID PK, CourseName), Result table (StudentID FK, CourseID FK, Marks). SQL: SELECT Name, Marks FROM Student JOIN Result ON Student.StudentID = Result.StudentID WHERE Marks > 60;

Key Notes — Exam Tips
DBMS vs RDBMS: DBMS stores data in files (no relationships); RDBMS stores in tables with relationships. MySQL is an RDBMS; early dBase was a DBMS.
ACID properties of transactions: Atomicity (all or nothing), Consistency (valid state), Isolation (concurrent transactions don't interfere), Durability (committed data persists).
SQL commands categories: DDL (CREATE, ALTER, DROP, TRUNCATE), DML (INSERT, UPDATE, DELETE), DQL (SELECT), DCL (GRANT, REVOKE), TCL (COMMIT, ROLLBACK, SAVEPOINT).
JOIN types: INNER JOIN (matching rows only), LEFT JOIN (all from left + matching from right), RIGHT JOIN (vice versa), FULL OUTER JOIN (all rows from both).
E.F. Codd proposed the relational model in 1970 and defined 12 rules for a true RDBMS. He is called the "Father of the Relational Database."
Summary — Database Fundamentals

Database = organized data collection. DBMS = software to manage it. RDBMS = stores in tables with keys (MySQL, Oracle, PostgreSQL). Keys: PK (unique row identifier), FK (links tables), Candidate, Composite. SQL categories: DDL (CREATE/DROP), DML (INSERT/UPDATE/DELETE), DQL (SELECT). Normalization: 1NF (atomic values), 2NF (no partial dependency), 3NF (no transitive dependency). ACID = Atomicity, Consistency, Isolation, Durability. NoSQL (MongoDB, Cassandra) = flexible schema, horizontal scaling for big data. E.F. Codd = Father of Relational Database.

Interview / Viva Questions

1What is the difference between a Primary Key and a Foreign Key?
Primary Key: uniquely identifies each row in its own table; cannot be NULL or duplicate (e.g., StudentID in Student table). Foreign Key: a column in one table that references the Primary Key of another table, establishing a relationship between the two (e.g., CourseID in Student table references CourseID in Course table).
2What are ACID properties in a database?
ACID: Atomicity (a transaction is all-or-nothing — if any part fails, everything rolls back), Consistency (transaction brings DB from one valid state to another), Isolation (concurrent transactions don't interfere with each other), Durability (once committed, data persists even after system crash).
3What is normalization? Explain 1NF and 3NF.
Normalization organizes a database to minimize redundancy. 1NF: all column values must be atomic (no repeating groups, no arrays in cells). 3NF: must be in 2NF + no transitive dependency (non-key columns must depend only on PK, not on other non-key columns). Goal: eliminate anomalies in insert, update, and delete operations.
4What is the difference between RDBMS and NoSQL?
RDBMS: structured data in tables with fixed schema, SQL language, ACID transactions, vertical scaling. Best for banking, ERP. Examples: MySQL, Oracle. NoSQL: flexible/dynamic schema, stores JSON documents/key-value/graph data, horizontal scaling, eventually consistent. Best for social media, big data, real-time apps. Examples: MongoDB, Redis, Cassandra.
5Write a SQL query to find all students with marks greater than 75, sorted by name.
SELECT s.Name, r.Marks FROM Student s JOIN Result r ON s.StudentID = r.StudentID WHERE r.Marks > 75 ORDER BY s.Name ASC;
