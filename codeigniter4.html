🚀 Section 01

Installation & Setup

CodeIgniter 4 requires PHP 8.0 or higher and supports installation via Composer (recommended) or manual download. CI4 introduces a .env configuration file, a built-in dev server via php spark serve, and the spark CLI tool — all significant improvements over CI3.

ℹ️
Requirements: PHP 8.0+, extensions: intl, mbstring, json, mysqlnd. Composer 2.x strongly recommended.
Method 1 — Composer Install (Recommended)

Composer handles dependencies and PSR-4 autoloading automatically. Preferred for all new CI4 projects.

💻 Terminal
# Create new project
composer create-project codeigniter4/appstarter my-project

# Navigate into project
cd my-project

# Copy env file and open it
cp env .env

# Start built-in dev server (http://localhost:8080)
php spark serve
Method 2 — Manual Download

Download zip from codeigniter.com/download, extract, and configure virtual host to point to the public/ folder.

💻 Apache / Nginx Config
# Apache — set DocumentRoot to /path/to/project/public
# Ensure mod_rewrite is enabled, AllowOverride All is set

# Nginx example
server {
    listen 80;
    server_name myapp.local;
    root /var/www/my-project/public;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php$is_args$args;
    }
    location ~ \.php$ {
        fastcgi_pass unix:/var/run/php/php8.1-fpm.sock;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
    }
}
Configure .env File

The .env file replaces CI3 config PHP files for environment-specific settings. Never commit this file to version control.

📄 .env
# ── Environment ──────────────────────────────
CI_ENVIRONMENT = development   # development | testing | production

# ── App ──────────────────────────────────────
app.baseURL      = 'http://localhost:8080/'
app.forceGlobalSecureRequests = false

# ── Database ─────────────────────────────────
database.default.hostname = localhost
database.default.database = my_database
database.default.username = root
database.default.password = secret
database.default.DBDriver = MySQLi
database.default.DBPrefix =
database.default.port     = 3306

# ── Session ──────────────────────────────────
app.sessionExpiration = 7200

# ── Encryption Key (run: php spark key:generate) ─
encryption.key = hex2bin(yourGeneratedKeyHere)
Generate Encryption Key
💻 Terminal
# Auto-generate and write key to .env
php spark key:generate

# Verify everything is OK
php spark --version
php spark env
✅
After setup, open http://localhost:8080 — you should see the CI4 welcome page with a green environment indicator.

Directory Structure

CI4 separates application code from the web root. Only public/ is exposed to the web — everything else stays private. This is a critical security improvement over CI3.

Controller — app/Controllers/User.php
🐘 PHP — Controller
<?php
namespace App\Controllers;

use App\Models\UserModel;
use CodeIgniter\Exceptions\PageNotFoundException;

class User extends BaseController
{
    /** List all users */
    public function index(): string
    {
        $model = new UserModel();
        return view('users/index', [
            'title' => 'All Users',
            'users' => $model->findAll(),
        ]);
    }

    /** Show single user */
    public function show(int $id): string
    {
        $model = new UserModel();
        $user  = $model->find($id);
        if ($user === null) {
            throw new PageNotFoundException(
                "User {$id} not found"
            );
        }
        return view('users/show', ['user' => $user]);
    }

    /** Handle POST form to create user */
    public function create()
    {
        if (! $this->validate([
            'name'  => 'required|min_length[3]',
            'email' => 'required|valid_email',
        ])) {
            return redirect()->back()
                ->withInput()
                ->with('errors',
                    $this->validator->getErrors());
        }
        (new UserModel())->insert(
            $this->request->getPost()
        );
        return redirect()->to('/users')
            ->with('success', 'User created!');
    }
}

🔀 Section 04

Routing

CI4 uses HTTP-verb based routing in app/Config/Routes.php. It supports RESTful resource routes, named routes, route groups with filters, closures, and wildcard placeholders — far more expressive than CI3's single array routing.

Basic Routes — app/Config/Routes.php
🐘 PHP — Routes.php
<?php
use CodeIgniter\Router\RouteCollection;
/** @var RouteCollection $routes */

// Basic HTTP verb routing
$routes->get('/', 'Home::index');
$routes->get('users', 'User::index');
$routes->get('users/(:num)', 'User::show/$1');
$routes->get('users/(:num)/edit', 'User::edit/$1');
$routes->post('users', 'User::create');
$routes->put('users/(:num)', 'User::update/$1');
$routes->patch('users/(:num)', 'User::patch/$1');
$routes->delete('users/(:num)', 'User::delete/$1');

// Match multiple methods
$routes->match(['get', 'post'], 'contact', 'Contact::index');

// Named route (use in views: route_to('user.show', 5))
$routes->get('users/(:num)', 'User::show/$1',
    ['as' => 'user.show']);

// Redirect route
$routes->addRedirect('old-path', 'new-path', 301);

(:any)Everything including slashespath/a/b/c
(:hash)Alphanumeric + dash/underscoreslug-value_1
Resource Routes (RESTful)
🐘 PHP — Resource
// One line generates all CRUD routes
$routes->resource('users');

// Limit to specific methods only
$routes->resource('photos', [
    'only' => ['index', 'show', 'create'],
]);

// Exclude specific methods
$routes->resource('tags', [
    'except' => ['delete'],
]);

Route Groups with Filters
🐘 PHP — Groups
// Admin group — protected by auth filter
$routes->group('admin',
    ['filter' => 'auth'],
    function($routes) {
        $routes->get('dashboard',
            'Admin\Dashboard::index');
        $routes->resource('users', [
            'namespace' => 'Admin',
        ]);
    }
);

// API v1 group with throttle
$routes->group('api/v1', [
    'namespace' => 'App\Controllers\Api',
    'filter'    => 'throttle:60,1',
    ], function($routes) {
        $routes->resource('users');
        $routes->resource('products');
    }
);

// Use named route in controller
return redirect()->route('user.show', [42]);

// Use named route in view
<a href="<?= route_to('user.show', 42) ?>">View</a>

Controllers

Controllers extend BaseController which auto-injects $this->request, $this->response, and $this->logger. CI4 supports typed parameters, return types, initController() for setup, and direct JSON responses for API development.

Request Object — $this->request
🐘 PHP — IncomingRequest
// ── POST data ─────────────────────────
$name  = $this->request->getPost('name');
$email = $this->request->getPost('email');
$all   = $this->request->getPost();

// ── GET / query params ────────────────
$id    = $this->request->getGet('id');
$page  = $this->request->getGet('page', 1);

// ── JSON body (APIs) ──────────────────
$json  = $this->request->getJSON(true);

// ── Headers ───────────────────────────
$auth  = $this->request
    ->getHeaderLine('Authorization');

// ── Detect request type ───────────────
$this->request->is('post');   // bool
$this->request->isAJAX();     // bool
$this->request->isCLI();      // bool
$this->request->isSecure();   // HTTPS?

// ── Get user IP ───────────────────────
$ip = $this->request->getIPAddress();

// ── File upload ───────────────────────
$file = $this->request->getFile('avatar');
if ($file->isValid() && ! $file->hasMoved()) {
    $file->move(WRITEPATH . 'uploads');

Models & Database

CI4's Model class provides built-in CRUD, pagination, soft deletes, timestamps, and inline validation. The Query Builder offers a fluent interface for complex queries. Database config lives in .env or app/Config/Database.php.

Model CRUD Methods
🐘 PHP — Model Operations
$model = new UserModel();

// ── READ ──────────────────────────────
$all    = $model->findAll();
$user   = $model->find(1);
$users  = $model->find([1, 2, 3]);
$first  = $model->first();
$count  = $model->countAll();

// ── WHERE + CHAINING ──────────────────
$active = $model
    ->where('status', 'active')
    ->where('age >', 18)
    ->orderBy('name', 'ASC')
    ->limit(10, 0)
    ->findAll();

// ── INSERT ────────────────────────────
$id = $model->insert([
    'name'  => 'Alice',
    'email' => 'alice@example.com',
]);

// ── UPDATE ────────────────────────────
$model->update($id, ['name' => 'Alice Smith']);

// ── DELETE ────────────────────────────
$model->delete($id);           // hard delete
$model->withDeleted()->findAll(); // include soft
$model->purgeDeleted();          // truly remove

// ── PAGINATION ────────────────────────
$users = $model->paginate(15); // 15 per page
$pager = $model->pager;
// In view: <?= $pager->links() ?>

🛡 Section 08

Filters (Middleware)

Filters run before or after a controller executes. Common uses: authentication, rate limiting, CORS headers, logging. Register in app/Config/Filters.php and apply globally, per HTTP method, or per route pattern.

Create a Filter
🐘 PHP — app/Filters/AuthFilter.php
<?php
namespace App\Filters;

use CodeIgniter\Filters\FilterInterface;
use CodeIgniter\HTTP\RequestInterface;
use CodeIgniter\HTTP\ResponseInterface;

class AuthFilter implements FilterInterface
{
    public function before(
        RequestInterface $request,
        $arguments = null
    ) {
        if (! session()->get('user_id')) {
            return redirect()
                ->to('/login')
                ->with('error', 'Please log in first');
        }
    }

    public function after(
        RequestInterface $request,
        ResponseInterface $response,
        $arguments = null
    ) {
        // Add security headers after response
        $response->setHeader(
            'X-Frame-Options', 'DENY'
        );
    }
}
Register in app/Config/Filters.php
🐘 PHP — Filters.php
// Register your filters with an alias
public array $aliases = [
    'csrf'     => CSRF::class,
    'toolbar'  => DebugToolbar::class,
    'auth'     => \App\Filters\AuthFilter::class,
    'api-auth' => \App\Filters\ApiAuthFilter::class,
    'role'     => \App\Filters\RoleFilter::class,
];

// Apply globally to ALL routes
public array $globals = [
    'before' => ['honeypot', 'csrf'],
    'after'  => ['toolbar'],
];

// Apply to specific HTTP methods
public array $methods = [
    'post'   => ['csrf'],
    'delete' => ['auth'],
];

// Apply to route URL patterns
public array $filters = [
    'auth'     => ['before' => ['admin/*']],
    'api-auth' => ['before' => ['api/*']],
];

// Apply in Routes.php (per route)
$routes->get('admin/dash', 'Admin::index',
    ['filter' => 'auth']);

// Multiple filters on one route
$routes->get('admin/users', 'Admin::users',
    ['filter' => ['auth', 'role:admin']]);
✅ Section 09

Validation

CI4 includes 30+ built-in validation rules, custom error messages, grouped rules, and model-level validation. Validate in controllers with $this->validate(), use withInput() to re-fill forms, and display errors from session flashdata.

Controller Validation
🐘 PHP — validate()
public function register()
{
    $rules = [
        'name' => [
            'label'  => 'Full Name',
            'rules'  => 'required|min_length[3]|max_length[50]',
            'errors' => [
                'required'   => 'Name cannot be empty',
                'min_length' => 'At least 3 characters needed',
            ],
        ],
        'email'    => 'required|valid_email|is_unique[users.email]',
        'password' => 'required|min_length[8]',
        'confirm'  => 'required|matches[password]',
        'age'      => 'permit_empty|integer|greater_than[17]',
        'role'     => 'required|in_list[admin,user,editor]',
    ];

    if (! $this->validate($rules)) {
        return redirect()->back()
            ->withInput()
            ->with('errors',
                $this->validator->getErrors());
    }
    // Passed — process data
    $data = $this->request->getPost();
}

🔒 Section 10

Session & Cookies

CI4 sessions support multiple drivers (files, database, Redis, Memcached). The new OOP Cookie class adds proper SameSite, Secure, HttpOnly flags — far more secure than CI3's simple cookie helper. Configure sessions via .env.

Session — Complete API
🐘 PHP — Session
$session = session(); // helper fn

// ── SET ───────────────────────────────
$session->set('user_id', 42);
$session->set([
    'user_id'   => 42,
    'username'  => 'alice',
    'role'      => 'admin',
    'logged_in' => true,
]);

// ── GET ───────────────────────────────
$id   = $session->get('user_id');
$name = $session->username; // magic prop
$all  = $session->get();

// Check key exists
if ($session->has('user_id')) { ... }

// ── FLASHDATA (shows once) ────────────
$session->setFlashdata('success', 'Saved!');
$msg = $session->getFlashdata('success');
$session->keepFlashdata('success'); // keep it

// ── TEMPDATA (auto-expires) ───────────
$session->setTempdata('token', 'abc', 300);

// ── REMOVE & DESTROY ─────────────────
$session->remove('username');
$session->remove(['username', 'role']);
$session->destroy(); // full logout
Cookies — OOP Cookie Class
🐘 PHP — Cookie
use CodeIgniter\Cookie\Cookie;

// ── SET (OOP style) ───────────────────
$cookie = new Cookie('theme', 'dark', [
    'expires'  => '+30 days',
    'path'     => '/',
    'secure'   => true,      // HTTPS only
    'httponly' => true,      // No JS access
    'samesite' => Cookie::SAMESITE_LAX,
]);
$this->response->setCookie($cookie);

// Shorthand helper
set_cookie('theme', 'dark', 86400);

// ── GET ───────────────────────────────
$theme = $this->request->getCookie('theme');
$all   = $this->request->getCookie(); // all

// ── DELETE ────────────────────────────
$this->response->deleteCookie('theme');
delete_cookie('theme'); // helper
⚠️
Never store sensitive data (user IDs, roles, tokens) in cookies. Cookies are client-side and can be read/modified. Use sessions for sensitive data.
ℹ️
Session drivers: files (default), database, redis, memcached. Set in .env via app.sessionDriver.
🔓 Section 11

Security — CSRF, XSS & Passwords

CI4 provides CSRF token protection auto-wired to forms, context-aware output escaping via esc(), and PHP native password hashing. Enable CSRF in app/Config/Security.php and always hash passwords with password_hash().

CSRF Config — app/Config/Security.php
🐘 PHP — Security.php
public string $csrfProtection = 'cookie';

Password Hashing
🐘 PHP — Passwords
// ── HASH on registration ──────────────
$hash = password_hash(
    $plainPassword,
    PASSWORD_BCRYPT,
    ['cost' => 12] // higher = slower = safer
);
// Store $hash in database, NEVER $plainPassword

// ── VERIFY on login ───────────────────
$user = (new UserModel())
    ->where('email', $email)->first();

if ($user && password_verify(
    $inputPassword, $user['password']
)) {
    session()->set([
        'user_id'   => $user['id'],
        'logged_in' => true,
    ]);
    return redirect()->to('/dashboard');
}

// ── REHASH if cost changes ────────────
if (password_needs_rehash(
    $user['password'],
    PASSWORD_BCRYPT, ['cost' => 12]
)) {
    $newHash = password_hash(
        $inputPassword, PASSWORD_BCRYPT
    );
    $model->update($user['id'], [
        'password' => $newHash
    ]);
}
🛑
Never store plain-text passwords. Never use MD5/SHA1 for passwords. Always use password_hash() with PASSWORD_BCRYPT or PASSWORD_ARGON2ID.

🐘 PHP — Custom Service
// app/Config/Services.php
namespace Config;
use CodeIgniter\Config\BaseService;
use App\Services\PaymentService;
use App\Services\NotificationService;

class Services extends BaseService
{
    public static function payment(
        bool $getShared = true
    ): PaymentService {
        if ($getShared) {
            return static::getSharedInstance('payment');
        }
        return new PaymentService(
            config('Payment')
        );
    }

    public static function notify(
        bool $getShared = true
    ): NotificationService {
        if ($getShared) {
            return static::getSharedInstance('notify');
        }
        return new NotificationService();
    }
}

Migrations & Seeders

Migrations version-control your database schema. Seeders populate tables with initial or test data. Together: php spark migrate:fresh --seed sets up a complete fresh database in one command — critical for team development and CI/CD.

Complete Migration Example
🐘 PHP — Migration
<?php
namespace App\Database\Migrations;
use CodeIgniter\Database\Migration;

class CreateUsersTable extends Migration
{
    public function up(): void
    {
        $this->forge->addField([
            'id' => [
                'type'           => 'INT',
                'constraint'     => 11,
                'unsigned'       => true,
                'auto_increment' => true,
            ],
            'name' => [
                'type'       => 'VARCHAR',
                'constraint' => '100',
            ],
            'email' => [
                'type'       => 'VARCHAR',
                'constraint' => '150',
                'unique'     => true,
            ],
            'password' => [
                'type'       => 'VARCHAR',
                'constraint' => '255',
            ],
            'role' => [
                'type'       => 'ENUM',
                'constraint' => ['user', 'admin'],
                'default'    => 'user',
            ],
            'active' => [
                'type'       => 'TINYINT',
                'constraint' => 1,
                'default'    => 1,
            ],
            'created_at' => ['type'=>'DATETIME', 'null'=>true],
            'updated_at' => ['type'=>'DATETIME', 'null'=>true],
            'deleted_at' => ['type'=>'DATETIME', 'null'=>true],
        ]);

        $this->forge->addPrimaryKey('id');
        $this->forge->addKey('email');
        $this->forge->createTable('users');
    }

    public function down(): void
    {
        $this->forge->dropTable('users');
    }
}

✅
Always write a down() method that exactly reverses up(). This ensures safe rollbacks in production deployments.
⚠️
Never edit a migration that has already been run. Create a new migration to alter existing tables instead.
